# Connectix VPN Bot — Multi-Tier Reseller Platform

ربات فروش VPN تلگرامی مبتنی بر Connectix Seller API، با پشتیبانی کامل از سیستم نمایندگی
چندسطحی (پلکانی/نامحدود)، کیف پول پیش‌پرداخت، چند روش پرداخت قابل‌تنظیم، و پنل مدیریت
تحت وب.

## معماری

این پروژه از دو بخش مستقل تشکیل شده:

```
┌─────────────────────────────────────────────────────────┐
│                      BACKEND (مرکزی)                      │
│  - تنها نگه‌دارنده‌ی توکن Connectix                          │
│  - دیتابیس: ربات‌ها، کاربران، کیف‌پول‌ها، سفارش‌ها، قیمت‌گذاری   │
│  - منطق سلسله‌مراتب نمایندگی + تسویه‌حساب کاسکیدی            │
│  - REST API برای کلاینت‌های ربات (api/)                     │
│  - پنل مدیریت تحت وب برای ادمین اصلی (admin/)               │
└─────────────────────────────────────────────────────────┘
                     ▲                      ▲
                     │ HTTP + API Key        │ HTTP + API Key
         ┌───────────┴──────────┐  ┌─────────┴───────────┐
         │   BOT CLIENT #1        │  │   BOT CLIENT #2       │
         │  (روی سرور اصلی اجرا     │  │  (روی سرور شخصی        │
         │   می‌شه)                │  │   یک نماینده اجرا می‌شه) │
         └────────────────────────┘  └───────────────────────┘
```

**نکته‌ی کلیدی:** ربات‌های تلگرامی (`bot_client/`) هیچ منطق قیمت‌گذاری، کیف‌پول یا
تماس مستقیم با Connectix ندارند. هر کاری فقط از طریق API بک‌اند مرکزی (`backend/`)
انجام می‌شه. به همین دلیل یک نماینده می‌تونه ربات خودش رو روی هر سروری اجرا کنه
(برای جلوگیری از اختلال/قطعی مشترک با بقیه)، در حالی که کنترل کامل (قیمت، دسترسی
نمایندگی، گزارش فروش، حتی توکن و آیدی ادمین) همچنان دست ادمین اصلی در بک‌اند
مرکزی می‌مونه.

## سلسله‌مراتب نمایندگی

- هر ربات یک رکورد `Bot` با `parent_bot_id` داره. ربات اصلی (ریشه) `parent_bot_id = NULL` داره.
- هر `Bot` برای هر پلن Connectix یک `PlanPricing` دارد: قیمتی که آن ربات از **والد خودش**
  می‌گیرد (`cost_price`، خودکار از قیمت فروش والد کپی می‌شود) و قیمتی که به مشتریان خودش
  می‌فروشد (`sell_price`، توسط ادمین همان ربات/نماینده تعیین می‌شود).
- وقتی سفارشی ثبت می‌شود: مبلغ `cost_price` از کیف‌پول همان ربات نزد والدش کسر می‌شود؛
  تفاوت `sell_price - cost_price` سود همان سطح است.
- عمق سلسله‌مراتب نامحدود است؛ ادمین اصلی می‌تواند برای هر ربات جداگانه، اجازه‌ی
  ساخت زیرنماینده (`can_create_sub_reseller`) را روشن/خاموش کند.

## راه‌اندازی سریع

### نصب/مدیریت با یک دستور

```bash
curl -fsSL https://raw.githubusercontent.com/Aziz-dev22/Connectix/main/install.sh | bash
```

این دستور یک منوی تعاملی نشان می‌دهد:

```
1) نصب
2) آپدیت
3) پشتیبان‌گیری کامل از پروژه
4) حذف پروژه
```

با انتخاب **۱) نصب**، دوباره می‌پرسد بک‌اند مرکزی نصب شود یا کلاینت ربات (برای
سرور شخصی یک نماینده)، و بعد همه‌ی مقادیر لازم (پورت، یوزر/پسورد پنل، توکن API
کانکتیکس، و در صورت تمایل توکن ربات اصلی + آیدی ادمین) را همان‌جا از شما
می‌پرسد — نیازی به ویرایش دستی `.env` نیست. در پایان، سرویس به‌صورت خودکار با
`systemd` بالا می‌آید (`Restart=always`).

**۲) آپدیت**: آخرین نسخه را از گیت‌هاب می‌گیرد، وابستگی‌ها را آپدیت و سرویس را
ری‌استارت می‌کند. **۳) پشتیبان‌گیری**: کل پوشه‌ی پروژه (شامل `.env` و دیتابیس)
را در یک فایل `tar.gz` در خانه‌ی کاربر ذخیره می‌کند. **۴) حذف**: با گرفتن تایید،
سرویس‌ها و تمام فایل‌های پروژه را پاک می‌کند.

> برای نصب غیرتعاملی/اسکریپتی هم می‌توانید مستقیم آرگومان بدهید:
> `... | bash -s -- backend` یا `... | bash -s -- bot`

پنل مدیریت در `http://SERVER_IP:PORT/admin` در دسترس است (PORT همان چیزی است
که در زمان نصب وارد کردید؛ پیش‌فرض `8000`).

### اجرای کلاینت ربات روی سرور شخصی یک نماینده

همان دستور بالا را روی سرور نماینده اجرا کنید و گزینه‌ی «کلاینت ربات» را
انتخاب کنید. از شما پرسیده می‌شود:
- آدرس بک‌اند مرکزی (`BACKEND_URL`)
- `API Key` ربات (از پنل مدیریت گرفته شده)
- توکن ربات تلگرام

### ساخت ربات نمایندگی

دو راه برای اجازه‌ی ساخت ربات نمایندگی وجود دارد:
- ادمین اصلی از پنل وب یا از داخل خودِ ربات، `can_create_sub_reseller` را برای
  یک ربات روشن می‌کند (مجوز عمومی برای همه‌ی کاربرانش).
- یا یک کاربر عادی از منوی «🤝 نمایندگی» درخواست می‌دهد، و ادمین همان ربات
  (از داخل ربات یا پنل وب) فقط همان یک کاربر را تایید می‌کند.

در هر دو حالت، کاربر مجاز از داخل ربات توکن ربات تلگرام و آیدی ادمین خودش را
وارد می‌کند؛ بک‌اند مرکزی یک رکورد `Bot` جدید با `parent_bot_id` = ربات فعلی
می‌سازد و API Key صادر می‌کند، و اگر ربات روی همان سرور مرکزی اجرا شود بلافاصله
زنده می‌شود (بدون ری‌استارت).

## امکانات ربات (سمت مشتری)

- 🧪 **تست رایگان**: پلنی که در Connectix نوعش `Free` باشد به‌صورت خودکار به‌عنوان
  پلن تست شناسایی می‌شود و هر کاربر فقط یک‌بار می‌تواند از آن استفاده کند.
- 🛒 **خرید سرویس** با قیمت‌گذاری پلکانی
- 💰 **کیف‌پول داخلی**: مشتری می‌تواند شارژ کند و دفعات بعد بدون نیاز به ارسال
  رسید، مستقیم از موجودی کیف‌پول بخرد.
- 🔗 **رفرال**: هر مشتری یک لینک دعوت اختصاصی دارد؛ با اولین خرید موفق هرکسی که
  با آن لینک بیاید، مبلغ پاداش (قابل‌تنظیم توسط ادمین، پیش‌فرض خاموش) به
  کیف‌پول معرف اضافه می‌شود.
- 🤝 **نمایندگی**: درخواست نمایندگی یا ساخت مستقیم ربات نمایندگی (در صورت داشتن مجوز)
- 🆘 **پشتیبانی**: پیام مستقیم به ادمین؛ ادمین با دستور `/reply <آیدی_تلگرام> <متن>` پاسخ می‌دهد.
- 📡 **عضویت اجباری در کانال** (قابل روشن/خاموش کردن توسط ادمین هر ربات)
- دکمه‌ی «⬅️ بازگشت به منو» (یا «❌ انصراف» در مراحل ورود متن) در همه‌ی صفحات

## پنل مدیریت تحت وب

ادمین اصلی از `/admin` به همه‌چیز دسترسی دارد: درخت کامل ربات‌ها و نماینده‌ها،
توکن و API Key هر ربات، قیمت‌گذاری، درگاه‌های پرداخت، کیف‌پول هر ربات، مدیریت
کاربران (مسدودسازی، اصلاح کیف‌پول)، تایید/رد درخواست‌های نمایندگی، و تنظیمات
هر ربات (کانال اجباری، پاداش رفرال، متن پشتیبانی).

## درگاه‌های پرداخت

چهار روش پشتیبانی می‌شود؛ سه‌تای اول به‌صورت مستقل، به‌ازای هر ربات، از داخل
خودِ ربات (یا پنل وب) روشن/خاموش می‌شوند؛ کیف‌پول همیشه در دسترس است (اگر
موجودی کافی باشد):

| روش | وضعیت پیاده‌سازی |
|---|---|
| کارت‌به‌کارت | کامل (کاربر رسید می‌فرستد → در صف تایید ادمین همان ربات) |
| درگاه پرداخت (زرین‌پال و مشابه) | اسکلت آماده در `backend/services/gateway.py` — نیاز به `MERCHANT_ID` شما |
| ارز دیجیتال | اسکلت آماده در `backend/services/crypto.py` — نیاز به تنظیم آدرس کیف‌پول/وبهوک |
| کیف‌پول داخلی | کامل — بدون نیاز به تنظیم، خودکار در دسترس است |

## محدودیت‌های شناخته‌شده / گام‌های بعدی

- اتصال واقعی به زرین‌پال و مانیتورینگ تراکنش کریپتو پیاده‌سازی نشده (نیاز به
  اطلاعات حساب شما دارد) — فقط اسکلت و TODO گذاشته شده.
- پنل وب فعلاً سبک و بدون فریم‌ورک جاوااسکریپتی است (Jinja2 ساده)، برای شروع کافی
  است و بعداً قابل ارتقاست.
- اجرای چند ربات مرکزی در یک پروسه با `asyncio` انجام می‌شود؛ تحت بار بسیار بالا
  (صدها ربات فعال) باید به چند پروسه/worker مهاجرت کرد.
- سیستم پشتیبانی ساده است: پیام مشتری مستقیم برای ادمین فوروارد می‌شود و ادمین
  با دستور `/reply` پاسخ می‌دهد — یک رابط گفتگوی کامل (threaded) نیست.
- برای عضویت اجباری در کانال، ربات باید از قبل **ادمین همان کانال** باشد وگرنه
  بررسی عضویت ممکن نیست (در این حالت، برای جلوگیری از قفل‌شدن ربات، عضویت
  به‌صورت پیش‌فرض تایید در نظر گرفته می‌شود).
- ساخت سایت فروش (علاوه بر ربات تلگرام) فعلاً در نقشه‌ی راه نیست.
